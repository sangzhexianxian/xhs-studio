# 踩过的坑

按"会让你白跑一趟"的严重程度排。

## 1. 字符串被逐字拆成一行一个字

`pages[1].lines` 应该是一个列表 `["第一处细节", "第二处细节"]`。
但模型（或你手写的 `note.json`）很爱把它写成用 `\n` 连接的一整段字符串。

渲染代码里写的是 `for ln in page["lines"]`，传入字符串时 Python 会逐字符迭代，
于是每一页都变成：

```
第
一
处
细
节
```

**修法**：`render.py` 的 `_clean_page()` 对 `lines / promise / cols / items / points`
做统一拆分（按 `\n ; ； |`）。这不只是兼容模型输出——手写 note 时也一样安全。

## 2. 中文折行的三个禁则

不做这些，单页看起来就是"很业余"：

| 禁则 | 反例 |
|---|---|
| 标点不落行首 | `…就是这里` / `，所以我` |
| 开括号不落行尾 | `（这是` / `《被讨厌的` |
| 末行不留 1–2 字 | `…贴` / `…的` |

第三条最容易被忽略，但它一眼就能看出来。
`wrap_cn()` 里做了「末行 ≤2 字则从上一行挪一个字回来」。

## 3. Noto CJK 的 ttc 索引

`NotoSansCJK-Regular.ttc` 是一个集合，**index=2 才是简体中文（SC）**。
用 index=0 得到的是日文字形——"直"、"复"、"骨"这些字会明显不对，
但很多人以为是字体渲染问题，查很久。

## 4. `fit()` 只做截断，不做缩字无限

`fit(text, ..., max_lines=2)` 的行为是：从大字号往小缩，直到行数 ≤ max_lines；
如果缩到下限还是超，就**截断**——后半句直接没了。

所以标题类字段请自己控制在 14 字内。
长标题不会"自动排好"，只会被砍掉，而砍掉的地方通常正好是关键信息。

## 5. Web Share 需要安全上下文

`navigator.share` / `canShare` 在 `https://` 或 `localhost` 才有；
用 `http://192.168.x.x:8000` 打开时通常不可用（浏览器策略）。
发布页会因此自动落到"逐个下载"。想要系统分享，就用真实域名 + https。

## 6. Android WebView 的几个固定坑

- `usesCleartextTraffic="true"`：内网 http 地址不开这个必白屏。
- `<input type=file>` 默认点了没反应：必须重写 `onShowFileChooser`（本仓库用不到，但如果你要加"上传稿子"功能就会撞上）。
- `addJavascriptInterface` 的方法必须标 `@JavascriptInterface`，否则 4.2+ 全部调不到，且**不报错**。
- 存相册：Android 10+ 用 `RELATIVE_PATH + IS_PENDING`；10 以下才需要 `WRITE_EXTERNAL_STORAGE`。

## 7. Ubuntu 上 `python3 -m venv` 报 ensurepip 不可用

```
The virtual environment was not created successfully because ensurepip is not available
```

不是 Python 坏了，是缺包：

```bash
sudo apt install python3-venv
```

## 8. Unicode 与 emoji

- 小红书标题里 emoji 会让某些字体（尤其 Noto 的 CJK 子集）画成方框，
  所以提示词里限制"标题不许有 emoji"。
- 如果一定要画 emoji，需要额外装 `NotoColorEmoji.ttf` 并使用支持彩色字体的绘制方式，
  PIL 的 `ImageFont` 对此支持有限，建议直接避开。

## 9. 一次只改一个变量

改版式时最容易犯的错：文案、字号、留白、颜色一起改，
结果效果变差也说不清是哪一项。

正确做法是**改一处、重渲染、看一眼**。
九张图重渲染只要几秒，不值得靠猜。
